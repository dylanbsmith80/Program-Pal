# Trainer Programming Style

Use this repository-tracked reference for non-sensitive, trainer-confirmed programming defaults. Client-specific goals, limitations, performance, and preferences remain in each client's private Google Drive memory and override these defaults when they conflict.

Source: trainer follow-up after reviewing existing workouts, 2026-08-30.

## Reps And Loading

- Use **8–12 reps** as the trainer's usual working range unless the exercise, goal, program phase, or client requires something different.
- Exercises such as calf raises may use higher repetitions.
- Do not guess exact working weights when the trainer has not supplied a stable baseline.
- The trainer usually selects load live during the session from current performance, readiness, technique, and known client history.
- In written programs, prioritize clear sets, reps, movement intent, and useful RPE or effort guidance. Include an exact load only when the trainer has confirmed that it is durable enough to program.
- Some clients fluctuate meaningfully from day to day. A prior load is evidence of capacity, not an automatic prescription for the next session.

## Session Density

- Program enough useful work to fill the entire scheduled session.
- Prefer modest over-programming to under-programming.
- When timing is uncertain, include a clearly marked optional exercise or block such as `If time` rather than leaving the session short.
- Time estimates must still be realistic about coaching, setup, equipment transitions, rest, and client pace.
- A client-specific slower pace, longer rest need, fixed warm-up, or other known session pattern overrides the general density default.

## Exercise Variety

- The desired amount of variety is client-specific; do not apply one universal novelty rule.
- Preserve important compound lifts, movement patterns, and measurable anchors when they support the goal.
- Vary accessories, exercise order, machine/free-weight format, or movement variation when it improves engagement without weakening progression.
- Some clients benefit from repeating a stable structure with modest variation. Others need more rotation to avoid boredom.
- Novelty must remain purposeful and should not replace progression, safety, or client-specific intent.

## Workout Interpretation

- Treat older workout files as evidence of prior programming, not as a perfect template or proof of completion.
- Trainer shorthand in an older workbook may describe a familiar local exercise or machine. Resolve unclear shorthand before carrying it into a new client-facing file.
- When a program is created but not yet performed, keep its status `planned` rather than using it as evidence of tolerance or progress.

## Test Folder Rule

- `Program pal/DylanS/` is a test folder, not a client record.
- Ignore the DylanS folder during normal client inventory, memory retrieval, workout comparison, and program design.
- Use DylanS materials only when the trainer explicitly says the task is a test or explicitly asks to use that folder.
